# AI 資料庫查詢功能使用說明

## 概述

本系統整合了 Ollama AI 模型，允許用戶使用自然語言查詢資料庫中的庫存、零件、工單等資料。

## 前置需求

### 1. 安裝 Ollama

#### Windows 安裝
1. 到 https://ollama.com/download 下載 Ollama for Windows
2. 執行安裝程式並完成安裝
3. 安裝完成後，Ollama 會自動啟動服務

#### 驗證安裝
打開命令提示字元並執行：
```cmd
ollama --version
```

### 2. 下載 AI 模型

建議使用 Llama 3.1 8B 模型（預設）：
```cmd
ollama pull llama3.1:8b
```

其他可用模型：
```cmd
ollama pull llama3:8b
ollama pull llama2:7b
ollama pull gemma:7b
ollama pull qwen:7b
```

### 3. 驗證模型下載
```cmd
ollama list
```

## 功能特色

### 1. 自然語言查詢
- 用中文提問，AI 會自動生成相應的 SQL 查詢
- 支援複雜的資料庫關聯查詢
- 智慧型格式化回答

### 2. 建議查詢
系統提供預設的查詢問題，包括：
- 目前有哪些零件庫存不足？
- 最近一週有哪些入庫記錄？
- 工單需求量最高的前10個零件是什麼？
- 哪些零件還沒有設定儲存位置？
- 目前有多少待處理的採購訂單？

### 3. 對話記憶功能
- **上下文理解**: AI可以理解延續性問題，如"那麼"、"這些"、"它們"等指代
- **會話管理**: 每個瀏覽器會話都有獨立的對話歷史
- **歷史記錄**: 系統會記住最近20輪對話的內容
- **智慧關聯**: AI會參考之前的問答來提供更準確的回答

### 4. 模型選擇
- 支援多種 AI 模型（動態載入已下載的模型）
- 即時切換模型
- 模型狀態監控
- 自動檢測可用模型

## 使用方法

### 1. 訪問 AI 查詢頁面
- 在主導航中選擇「報表分析」→「AI 資料庫查詢」
- 或直接訪問 `/reports/ai-query`

### 2. 檢查連接狀態
- 頁面載入時會自動檢查 Ollama 服務狀態
- 綠色表示連接正常，紅色表示有問題
- 點擊「檢查連接狀態」按鈕可手動重新檢查

### 3. 選擇模型
- 系統會自動載入已下載的可用模型
- 在模型設定區選擇要使用的 AI 模型
- 點擊「設定模型」按鈕確認
- 如果沒有可用模型，系統會提示需要下載模型

### 4. 對話記憶
- 在輸入框中輸入問題（支援中文）
- 可以使用延續性問題，如"那麼...？"、"這些零件..."
- AI會參考之前的對話來理解上下文
- 點擊「查詢」按鈕或按 Enter 鍵

### 5. 管理對話歷史
- 會話ID顯示在輸入區域下方
- 點擊「清除歷史」可重新開始對話
- 每個會話最多保留20輪對話記錄

### 6. 查看結果
- AI 回答會顯示在聊天歷史中
- 可點擊「顯示SQL查詢」查看生成的 SQL 語句
- 結果會包含查詢到的記錄數量

## 查詢範例

### 基本查詢
- "有多少個零件？"
- "庫存數量最多的前10個零件是什麼？"
- "倉庫A有多少種零件？"

### 延續性對話範例
**對話1:**
- 用戶: "查詢零件表中有多少筆記錄"
- AI: "零件表中有3720筆記錄"
- 用戶: "那麼倉庫表呢？"
- AI: "倉庫表中有5筆記錄"
- 用戶: "這兩個表中，哪個記錄比較多？"
- AI: "零件表的記錄比較多，有3720筆，而倉庫表只有5筆"

**對話2:**
- 用戶: "顯示前5個零件的編號和名稱"
- AI: 顯示零件列表
- 用戶: "這些零件有庫存嗎？"
- AI: 根據前面查詢的零件檢查庫存狀況

### 庫存相關
- "有哪些零件庫存不足？"
- "庫存數量最多的前10個零件是什麼？"
- "倉庫A有多少種零件？"

### 工單相關
- "工單需求量最高的零件有哪些？"
- "有哪些工單需求但零件庫沒有的零件？"
- "工單 WO-001 需要哪些零件？"

### 交易記錄
- "最近一週有哪些入庫記錄？"
- "昨天有哪些出庫記錄？"
- "零件 P001 的最近異動記錄？"
- "今天有哪些庫存交易？"
- "最近三天的庫存異動統計"

### 採購相關
- "有多少待處理的採購訂單？"
- "即將到期的採購訂單有哪些？"
- "採購金額最高的訂單是什麼？"

## 故障排除

### 1. AI 服務無法連接
檢查事項：
- Ollama 服務是否正在運行
- 防火牆是否阻擋了連接
- 重新啟動 Ollama 服務

解決方法：
```cmd
# 檢查 Ollama 服務狀態
ollama ps

# 重新啟動 Ollama
# Windows: 在服務管理員中重新啟動 Ollama 服務
```

### 2. 模型不可用
檢查事項：
- 模型是否已下載
- 模型名稱是否正確

解決方法：
```cmd
# 檢查已下載的模型
ollama list

# 重新下載模型
ollama pull llama3.1:8b
```

### 3. SQL查詢錯誤
可能原因：
- 資料庫路徑錯誤
- 表名不正確
- AI模型生成的SQL語法錯誤

解決方法：
- 確認資料庫檔案位於 `instance/hardware.db`
- 檢查表名是否正確（如 `inventory_transactions` 而非 `inventory_transaction`）
- 嘗試使用不同的AI模型
- 簡化查詢問題

## 系統需求

### 硬體需求
- RAM: 建議 8GB 以上（模型會佔用記憶體）
- 硬碟: 每個模型約需 4-8GB 空間
- CPU: 支援 AVX2 指令集（現代 CPU 都支援）

### 軟體需求
- Windows 10/11
- Python 3.8+
- Ollama 最新版本

## 注意事項

1. **資料安全**: AI 模型在本地運行，查詢的資料不會傳送到外部服務
2. **性能**: 首次使用模型時可能較慢，後續查詢會更快
3. **精確度**: AI 生成的 SQL 可能不總是完美，建議驗證結果的合理性
4. **資源使用**: AI 模型會佔用系統資源，在資源有限的環境中請注意
