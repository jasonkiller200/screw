# Session 過期問題分析與解決方案

## 📋 問題分析

### 現有風險

#### 1. **Session 配置**
```python
# app.py
app.config['PERMANENT_SESSION_LIFETIME'] = timedelta(hours=8)
```

**問題場景**：
- 用戶早上 9:00 登入系統
- 瀏覽器標籤頁保持開啟，但用戶去開會/午休
- 下午 5:00 後 Session 過期（超過 8 小時）
- 用戶返回繼續操作 → **API 請求被拒絕**

#### 2. **可能發生的嚴重問題**

| 風險類型 | 具體場景 | 影響 | 嚴重度 |
|---------|---------|------|-------|
| **資料寫入失敗** | 提交出庫單時 Session 已過期 | 資料完全丟失，需重新填寫 | 🔴 高 |
| **靜默失敗** | 前端顯示成功但後端返回 401 | 庫存未扣減，帳實不符 | 🔴 極高 |
| **部分寫入** | 關聯資料插入到一半時 Session 過期 | 資料不完整，需手動修正 | 🟡 中高 |
| **庫存錯誤** | 盤點/調整時 Session 過期 | 庫存數據錯誤 | 🔴 極高 |
| **審查失效** | 審查週期訂單時過期 | 審查記錄丟失 | 🟡 中 |

#### 3. **實際測試場景**

```
時間軸：
09:00 - 用戶登入
12:00 - 去吃午餐（瀏覽器標籤保持開啟）
14:00 - 繼續工作（Session 還有效）
17:00 - Session 過期（8 小時到期）
17:30 - 提交出庫單 → ❌ 401 錯誤，資料丟失
```

### 核心功能

#### 1. **自動心跳續期**

```javascript
// 每 30 分鐘自動發送心跳
setInterval(async () => {
    await fetch('/api/session/heartbeat', { method: 'POST' });
    // Session 有效期自動延長 8 小時
}, 30 * 60 * 1000);
```

**效果**：
- ✅ 只要用戶頁面保持開啟，Session 永不過期
- ✅ 無需手動刷新頁面
- ✅ 背景自動運行，用戶無感知

#### 2. **過期前警告**

```javascript
// Session 剩餘 10 分鐘時顯示警告
if (remaining <= 10 * 60 * 1000) {
    showWarning("您的登入即將過期");
    // 提供「延長登入」按鈕
}
```

**用戶體驗**：
```
┌────────────────────────────────────────┐
│  ⚠️  登入即將過期                      │
│                                        │
│  您的登入狀態將在 8 分鐘後過期         │
│                                        │
│  ┌──────────────────────────────┐     │
│  │  🔄 延長登入時間              │     │
│  └──────────────────────────────┘     │
└────────────────────────────────────────┘
```

#### 3. **401 錯誤攔截**

```javascript
// 攔截所有 Fetch 請求
window.fetch = async function(...args) {
    const response = await originalFetch(...args);
    
    if (response.status === 401) {
        // 立即導向登入頁面
        handleSessionExpired();
    }
    
    return response;
};
```

**防護效果**：
- ✅ 任何 API 返回 401 立即處理
- ✅ 防止靜默失敗
- ✅ 保護資料完整性

#### 4. **用戶活動監控**

```javascript
// 監控用戶活動
['mousedown', 'keydown', 'scroll', 'touchstart'].forEach(event => {
    document.addEventListener(event, resetActivityTimer);
});
```

**智能化**：
- 🎯 用戶活動時更頻繁檢查
- 🎯 長時間無活動時減少檢查
- 🎯 節省伺服器資源

## 🔒 安全考慮

### 已實施的安全措施

1. **HttpOnly Cookie**
   ```python
   app.config['SESSION_COOKIE_HTTPONLY'] = True
   ```
   防止 XSS 攻擊竊取 Session

2. **驗證每個心跳請求**
   ```python
   @login_required  # 必須是已登入用戶
   ```

3. **不在前端存儲敏感資訊**
   - 只記錄 Session 開始時間
   - 不存儲 Session ID 或 Token

4. **自動清理過期 Session**
   - Flask 自動管理 Session 過期
   - 過期後無法續期

### 額外建議

1. **HTTPS 部署**
   - 已啟用 SSL (cert.pem)
   - 防止 Session 劫持

2. **定期更新密鑰**
   ```python
   # 使用環境變數管理
   app.secret_key = os.environ.get('SECRET_KEY')
   ```

3. **限制心跳頻率**
   ```python
   # 可添加速率限制
   from flask_limiter import Limiter
   limiter.limit("120/hour")(session_heartbeat)
   ```

## 📞 技術支援

### 常見問題

**Q: 心跳會增加伺服器負載嗎？**
A: 影響極小。每個用戶每小時僅 2 次心跳請求，1000 個用戶也只有 2000 次/小時。

**Q: 用戶關閉瀏覽器後 Session 會怎樣？**
A: Session 在伺服器端保持有效（8 小時），但心跳會停止。重新開啟瀏覽器需重新登入。

**Q: 可以完全禁用過期嗎？**
A: 不建議。Session 永不過期會造成安全風險。目前 8 小時 + 自動續期已經很寬鬆。

**Q: 手機 PWA 也有效嗎？**
A: 是的。只要 PWA 在背景運行，心跳會持續工作。
