## 專案藍圖：即時庫存調整功能

**專案目標：**
提供一個僅限管理員使用的快速操作介面，用於處理日常發現的單品項庫存不符問題，並產生可追溯的庫存調整紀錄。

---

### **階段一：後端 API 與權限**

**Epic 1.1: 建立安全且功能完整的調整 API**

*   **User Story 1.1.1: 開發庫存調整 API 端點**
    *   **描述：** 開發一個後端 API 端點，接收前端傳來的調整數據，計算差異並更新庫存。
    *   **任務：**
        *   在 `controllers/inventory_controller.py` 中建立 `POST /api/inventory/adjust-stock` 端點。
        *   API 應接收 `part_id`, `warehouse_location_id`, `new_quantity` 及 `notes`。
        *   後端需查詢目前的庫存，計算與 `new_quantity` 的差異。
        *   呼叫 `CurrentInventory.update_stock` 方法，傳入計算出的差異值，並將 `transaction_type` 設為 `ADJUST`。
    *   **驗收標準：**
        *   API 能成功接收請求並正確更新 `CurrentInventory`。
        *   `InventoryTransaction` 表格中產生一筆類型為 `ADJUST` 的新紀錄。
    *   **進度與備註 (2025-10-23)：** 完成。

*   **User Story 1.1.2: 為 API 端點加上管理員權限**
    *   **描述：** 確保只有具備管理員權限的使用者才能呼叫此 API。
    *   **任務：**
        *   研究現有的使用者認證與角色系統 (例如 `User` 模型中的 `role` 欄位)。
        *   建立或使用一個裝飾器 (Decorator) 或在端點函式內部進行檢查，驗證 `current_user.role`是否為 'admin'。
    *   **驗收標準：**
        *   管理員使用者可以成功呼叫 API。
        *   非管理員使用者呼叫 API 時會收到 403 (Forbidden) 或類似的權限錯誤。
    *   **進度與備註 (2025-10-23)：** 延後處理。經討論，因系統尚無完整登入機制，此項待未來導入權限系統時再一併實作。

### **階段二：前端介面開發**

**Epic 2.1: 建立使用者操作介面**

*   **User Story 2.1.1: 建立庫存調整頁面路由與模板**
    *   **描述：** 建立一個讓使用者可以進行操作的網頁。
    *   **任務：**
        *   在 `controllers/web_controller.py` 中建立 `GET /inventory/adjustment` 路由。
        *   保護此路由，僅限管理員存取。
        *   建立 `templates/inventory/adjustment.html` 模板檔案。
        *   模板應包含零件搜尋、儲位選擇、新數量輸入框和備註欄位。
    *   **驗收標準：**
        *   管理員可透過 `/inventory/adjustment` 存取頁面。
        *   非管理員存取時應被阻擋。
        *   頁面應包含所有必要的操作元件。
    *   **進度與備註 (2025-10-23)：** 完成。路由與模板已建立，但權限保護部分延後處理。

*   **User Story 2.1.2: 開發前端互動邏輯**
    *   **描述：** 為調整頁面編寫 JavaScript，處理使用者互動與 API 呼叫。
    *   **任務：**
        *   建立 `static/js/inventory/adjustment.js` 檔案。
        *   實作零件搜尋功能。
        *   根據選擇的零件，動態載入其所在的儲位選項。
        *   「確認調整」按鈕被點擊時，收集所有數據並呼叫 `POST /api/inventory/adjust-stock` API。
        *   向使用者顯示成功或失敗的訊息。
    *   **驗收標準：**
        *   使用者可順暢地搜尋零件、選擇儲位、輸入數量並提交。
        *   提交後能正確呼叫後端 API。
        *   操作結果能清晰地反饋給使用者。
    *   **進度與備註 (2025-10-23)：** 完成。
